# WAX micro-market trading profile

LEEF Trader targets WAX/Antelope micro-liquidity books. The engine must support small executable clips, multi-pool routes, and a higher opportunity cadence than a conventional large-market bot. Higher cadence is not permission to manufacture volume at any price.

## Default WAX profile

New WAX/LEEF bot sessions use the bounded WAX Micro Active profile:

- 10-second book polling and cooldown, with a 60 execution-attempts-per-hour cap.
- 4% directional price-impact ceiling and 0.8% slippage tolerance.
- 55% engine confidence floor and 0.2% directional edge floor.
- Up to 4 configured route hops (the Volume Maker path itself is capped at 3).
- 7.5% maximum pool-share sizing.
- 1.5% maximum loss per volume echo, with the existing $5 session echo budget and account-level drawdown/daily-loss breakers.

A saved profile is migrated only when it exactly matches the untouched previous WAX defaults. Customized risk settings are preserved. Users can still select Conservative, Balanced, Standard, or WAX Micro Active.

## Volume selection

- Volume Maker evaluates a deterministic size ladder for each supported holding rather than sampling one pseudo-random size per token.
- It ranks clips by expected net USD after route fees, impact and executable exit checks. Notional is only a tie-breaker.
- Auto is an opportunity selector, not an implicit Grid strategy: it does not create an unanchored grid-seed buy. The explicit Grid strategy owns seed entries.
- The Auto strategy first selects a positive expected-value candidate. If none exists, it may try a bounded atomic echo, then a bounded multi-pool LEEF tape clip. The tape is still subject to the session echo budget and exact on-chain min-out floor.
- Multi-hop routes are never approved from oracle marks alone; the planner compares the executable reverse route to reject phantom mark-based gains.
- The live executor re-quotes through Alcor and validates exact transfer settlement. A planner estimate is never treated as a fill.

## JEV CONTROL

JEV receives one question for one code-generated candidate:

> Should this exact candidate execute now? YES or NO.

The candidate's action, tokens, contracts, size, pools, route and expected economics are generated by the deterministic engine. JEV cannot change them. A YES is bound to the candidate fingerprint and freshness metadata. The deterministic risk checks, Alcor quote and chain settlement remain authoritative. A missing, stale, malformed or low-confidence answer fails closed.

## AI model responsibilities

The signer strategic AI helper and JEV are separate:

- Strategic review uses the OpenAI-compatible PPQ route. The current Cloudflare Worker is configured with `PPQ_MODEL=openai/gpt-oss-20b`.
- JEV CONTROL uses TypeSafe `jev-latest` through the signer's TypeSafe provider.
- Neither model discovers or signs trades. The route optimizer and execution guards own that.

Do not rotate the signer model based on subjective chat quality alone. Benchmark candidate models on the same anonymized market snapshots and score route/economic reasoning, JSON validity, latency, token cost, and agreement with deterministic outcomes before changing the production model.

## Validation

Run the planner and risk-profile unit tests, full typecheck/lint/test/build suite, and paper-mode replay against recorded WAX market snapshots before enabling live sessions. Measure realized net P&L, actual fees, confirmed pool volume, rejection reasons and recovery incidents separately.


## Persisted bot migration and live-lock recovery

- Bot store schema v16 is the migration boundary for untouched v15 WAX/LEEF defaults. Without the version bump, Zustand does not invoke the migration for an existing v15 save.
- The live capital lock records the originating account and start time for each bot signing attempt.
- Anchor/Cloud Wallet performs signing and broadcast outside the app. A definitive user cancellation releases the in-flight signing lock; an ambiguous wallet error with no transaction ID remains blocked.
- A txid-less interrupted lock can only be released through the Bot Desk's two-step operator acknowledgement after checking the **same WAX account's** activity from the recorded start time. A lock with a txid still requires transaction reconciliation; malformed lock storage is never self-clearable.
- A session-key broadcast timeout records the known transaction ID but never unlocks inside the signer. The bot loop first appends the exact unresolved execution, then read-only recovery verifies the transfers, applies the position update idempotently, settles the journal, and only then releases live capital.
- The recovery acknowledgement is an explicit user attestation, not an automated proof that no transaction landed. When history is incomplete or ambiguous, keep the lock and escalate for transaction-state review.
